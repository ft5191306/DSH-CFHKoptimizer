# dsh-cf-pin — 优选线路

持续测量 `open-design.ai` 这条链路上的 Cloudflare 边缘 IP，链路劣化时自动改写
`hosts` 的优选段。

这个插件是同一份测量策略的**常驻化版本**：原来的手动脚本 `cf_pin.py` 保留为
手动逃生通道（需要从头扫一遍、或怀疑候选池本身时用它）。

当前版本 **v0.2.3**（`package.json` 的 `version` 与此一致）。
图标规格见 [UI-SPEC.md](UI-SPEC.md)。

## 更新日志

### v0.2.3

第二轮审计（2026-10-30 晚）发现上一轮「修好了」的东西里还有两处**口径没对齐**、
两处**没有任何回归保护**。本轮全部修掉，并把断言 192 → 227。

- **`snapshot.best` 与 `decide()` 共用同一份派生**（`Engine.selectBest()`）。
  上一轮修「`best` 忽略 `certFailures`」时只加了一道 cert 过滤，仍然只取
  `qualified`；而 `decide()` 的规则是「没有合格候选就退到相对择优」。两套口径于是
  分叉：全部候选都在丢包时，`decide()` 给出 `write:true, candidateIp:X`（这一拍真的
  会写 hosts），`snapshot.best` 却是 `null`，界面「更快候选」显示「没有」。上一轮的
  缺陷是「推荐一条切不过去的线」，修完变成「说没有、实际在切」，是同一类错误的
  另一个方向。现在两边都调 `selectBest()`，不可能再分叉。
- **状态码不再被 `all-degraded` 遮住**：`resolveState()` 里「候选全部不合格」那条
  兜底排在 `no-candidate` 之前，于是「这些 IP 的证书不适配这个域名」被渲染成
  「线路全都偏慢」。两句完全不同的话，而且把用户往错误方向带。现在 `no-candidate`
  优先。
- **结果文案与阶段分成两格**（`manualResult`）：先点「立即检测」、未结束时点
  「立即切换」，`/apply` 先完成会写下「已切到 X」，接着 `/scan` 返回把它设成
  brake/"测速完成"、brake 到点又清空——**用户永远看不到那次切换的结果**。
  现在阶段转换碰不到结果格，结果只受自己的 `MANUAL_NOTE_MS` 存活期约束。
- **手动检测的取样方式换掉**：上一轮只把「读机房」的宽度从 12 提到 40，截断仍然
  按 TCP rtt 做。但本文件自己写着「TCP 不能排序」——用一段已知不可排序的量决定谁
  进实测，等于扔掉 2/3 的候选池。实测过一组「TCP rtt 递增、真实延迟递减」的网络：
  改之前手动检测给出的最优候选 460ms，而真正最快的那条（100ms）从没被测过；
  同一网络下自动轮靠 `rotation` 三轮就全覆盖了。现在按「近端机房 → 读机房真实
  耗时」排序，再按独立的 `manualRotation` 轮换起点，并排除 hosts 里已钉住的 IP。
- **补上真正缺的那层断言**：`index.js` 以前从未被 import，于是把 `/apply` 的收尾
  改回 `if (result?.merged !== true)`、甚至整行删掉，**192 条断言一路全绿**，
  而「卡 90 秒」可以原样复活。现在 `[ROUTE]` 段用假 `ctx` 真的跑起插件的 9 条路由
  并 `fetch` 一次 `/apply`，断言「请求返回时 manual 已收尾」——收尾写在哪一层都能过，
  拆掉就必红。另加 `[BEST]` / `[STATE]` / `[SCANPICK]` / `[SCANEXCL]` 四段行为断言。

### v0.2.2

审计发现并修掉六处缺陷，其中前四条有对应行为断言。

- **全超时重扫从死代码变成真的会跑**：`runCandidateRound` 把 `roundRunning` 置真后
  递归调用自己来重扫，进来第一行就被同一个入口守卫挡掉——**重扫一次都没执行过**，
  且那条 `return` 还跳过了本轮判定。现在拆成入口（独占 + 计时 + 异常兜底）与本体
  `runCandidateRoundOnce`（无守卫），重扫调本体，`allowRescan` 继续防无限递归。
- **证书失败记忆不再被兜底绕过**：`decide()` 与 `runApply()` 原来都写
  `healthy.length > 0 ? healthy : this.candidates`，于是候选**全部**被判死时回退到
  全量，下一拍重新握手、注定失败、3 秒后再来一遍。现在全部被判死时如实给
  `no-candidate` / 直接失败并说明原因。`candidates` 为空（还没测过）与「全被判死」
  分开措辞——前者说「证书都不适配」是谎话。
- **快照补上 `tier` 与 `certFailed`**：`tier` 以前算出来就丢掉了，「分档降级是否生效」
  在快照上根本无法验证。同时补了 `types.js` 里漏掉的 `streaming` / `advantageMs` /
  `thresholdMs` —— `snapshot.best` 现在与 `decide()` 用同一套证书过滤，不会推荐一条
  永远切不过去的线路。
- **合并写入后手动阶段不再卡 90 秒**：`/apply` 原来只在 `merged !== true` 时收尾，
  但合并的目标可能是**自动路径**的写入，那条路径不管 manual 阶段，于是 `write` 阶段
  一直挂到 `MANUAL_TTL_MS` 过期——图标持续「写入中…」、配置页三个按钮全灰。
  收尾逻辑移到引擎的 `finishManualWrite()`，无条件执行、且只在阶段仍是 `write` 时动。
- **手动检测读机房的宽度对齐自动轮**（12 → 40）：那段 `hits` 是按 TCP rtt 排的，
  而 TCP 不可排序是实测结论，截前 12 名等于砍掉候选多样性；`runManualScan` 末尾又
  会把这份结果提升为 `this.candidates`，自动切换接着就用它。
- **测试补了行为层**：新增假探针注入口（`options.probe`），候选轮的级联/分档/重扫
  第一次有离线行为断言（此前只有源码正则，正是它让「重扫是死代码」躲过 154 条检查）。
  regression 从 154 条增至 192 条。

## 为什么需要它

这些域名走 Cloudflare anycast，同一条线路上会落到不同机房。境外链路默认常被甩到
LAX，国际链路丢包严重：API 请求动辄秒级超时。而 `162.159.x` / `104.26.x` 这一段
会落到 HKG，同一个请求 200ms 出头。`hosts` 把域名钉到特定边缘 IP 就能改掉落点。

IP 会慢慢劣化。手动跑 `cf_pin.py` 要快一分钟，而「变慢」这件事用户是事后才察觉的。
所以这个插件做的是：**平时不打扰，劣化时自己换掉。**

## 职责边界（重要）

**不做全量发现。** IP 已经过多轮实测选好，插件不重复这件事。它只做两件：

1. 判断当前链路是否劣化（相对一个更快的候选，差距是否 ≥ 150ms；全都烂时退到
   「相对择优」——见下面的判定与写入）
2. 该换时按 `cf_pin.py` 的同一套安全规则写 `hosts`；都不值得固定时，也能把
   `hosts` 里的固定段整个撤掉（取消固定）

需要从头扫一遍、或怀疑候选池本身时，仍然去跑 `cf_pin.py`。

## 测量口径（全部来自 cf_pin.py 的实测校准，不是这里拟的）

| 项 | 值 | 理由 |
|---|---|---|
| 采样窗口（候选） | **20s 硬上限** | 约 40 个样本，p95 才真正代表「1/20 的偶发卡顿」；5s 窗口的 p95 几乎等于最差值 |
| 采样窗口（当前 IP） | **自适应，1.2s 起**；上限 `clamp(采样间隔 − 500ms, 1.2s, 6s)`（默认间隔 6s → 5.5s） | 按上一拍 p50 外推，正好装下 3 个样本；上限绝不挤占下一拍。窗口写死 1.2s 会短于单次超时 1.5s，慢线路只能采到 1–2 个样本，`reliable` 永远不成立，自动切换在烂网络上永久停在「观察中」 |
| 采样间隔 | 50ms（候选）/ 100ms（当前） | 这是下限而非节拍：实际节奏由 RTT 决定，同一地址不并发抢带宽 |
| 单次 HTTPS 超时 | 1.5s | 完整请求正常约 500ms。用 TCP 的 0.3s 会把健康请求全误判成超时 |
| 超时记账 | **按 999ms 计入样本，不丢弃** | 丢弃会让「10 次卡 1 次」的 IP 看起来完美，而那一次卡顿正是用户感知到的 |
| 淘汰 | **超时次数 ≥ 3，或丢包/超时 ≥ 7.5%**，判「时断时续」 | 两道门是同一个判据的两种量法：n=40 时 7.5% 正好是 3 次超时；样本窗口更短时绝对门更早生效，2 个样本里 1 个超时不会被放过。「慢」和「断」是两件事：零丢包、每次都要 1 秒多只是慢，按相对 p50 排序即可；会随机卡死的才不能写进 hosts |
| 分档 | 按 **timeouts / loss** 分三级：`clean`（零超时零丢包）→ `ok`（零星丢包，未判断）→ `degraded`（判断） | 级联降级按档位走，**不按 p95 的数值**。超时记 999，但**成功样本也能 >999**，所以「p95 ≥ 999」既可能是真丢了 5% 请求，也可能一次没丢、只是慢（实测某 IP `p95=1401ms` 而 `loss=0%`）。拿 p95 判档会把「慢但健康」的线路打成「断」 |
| 排序 | 先档位，同档内按各地址 p50 平均；p50 相同再按 p95 | 实测同一批候选连跑 4 个 6s 窗口：p50 跨窗口极差平均 **7ms**，p95 是 **220ms**（32 倍）。用一个波动 32 倍的量当主排序键，名次基本是抛硬币，所以 p95 **只做 tiebreak** |
| 百分位 | 线性插值（numpy 口径），只用于 p50 / p95 读数 | 淘汰与分档都不由百分位决定，改看丢包/超时；p95 只作展示与 tiebreak |
| 全超时兜底 | 一轮里**每个候选都零成功样本** → 重新粗筛一次（只重试一次） | 候选池来自 256 个 IP 的粗筛，而粗筛只在那一刻判「TCP 通不通」。若粗筛恰好赶上网络抖动，池子本身就是坏的，之后怎么降级都救不回来——只能重扫 |
| TCP | 只做存活粗筛 | 实测 8 个 IP 的 TCP 全在 78~103ms（噪声内），HTTPS p50 却是 257~385ms；TCP 第一名在 HTTPS 排第四 |
| 候选池 | 162.159/16 + 104.26/16，各隔 2 个 /24 取 1 = 256 | 实测这一步拿到的近端候选比全量扫描还多，且快 3 倍 |
| 近端机房 | HKG NRT KIX ICN SIN TPE BKK MNL SGN | 远端机房差一个数量级（HKG ~500ms vs LAX ~2600ms），不进候选 |

**两条节奏是分开的，新鲜度差 25 倍：**

- 当前 IP：默认 **6 秒**测一次，取**最新一次**值（无滚动窗口）；每一拍内部的采样
  窗口按上一拍 p50 自适应，从 1.2s 起放宽，封顶在「采样间隔 − 500ms」（默认 5.5s）。
  它要能立刻反映此刻的体感。
- 候选轮：默认 **150 秒**一轮（12 候选 ÷ 2 并发 × 25s 槽位）；两轮之间隔一个
  由并发推导的间隔（并发 2 → 3 分钟，见「配置」一节），不是固定 5 分钟。

任何把这两个数并排展示的界面都必须带上各自的年龄。

## 判定与写入

- 阈值：候选最优 p50 比当前低 **≥ 150ms**
- **无地板值、无「连续 N 轮」、无回切冷却**（用户明确否决过这些阻尼）
- **全劣化也切，按「相对择优」**：所有候选都在丢包时，取「丢包少 → p50 小」的
  第一条；要求它比当前 p50 低 ≥ 阈值、且丢包率不高于当前。切完状态是
  `degraded-switched`，快照里 `lastSwitchDegraded=true`——与 `switched`
  （有合格候选的常规切换）分开说，不把「矮子里拔将军」报成「找到了更快的线路」
- 全劣化但这次**没有写成**（不够阈值 / 丢包更差 / 自动关闭 / 只差权限等）→
  状态 `all-degraded`；手动降级写入与「取消固定」两个出口始终可用
- 有思考流在飞 → 状态「等待写入」，流结束立刻写并**重新判定一次**（避免照着过时结论改 hosts）
- `probeWhileThinking=false` 时，思考流期间**跳过采样**，流结束后下一拍补测
- 当前读数不可信（样本数 < 3 **且** 丢包不足 50%）→ 判为「观察中」，不写：
  单样本的 p50 是噪声，不足以支撑改 hosts。丢包过半本身就是明确的坏证据，样本
  再少也认——死线路上只采到 1 个样本时，自动切换必须看得见它
- 写前闸门：启用的地址逐个做**真实证书链 + 主机名校验**。HTTP 状态码不参与判定
  （`amr-link` 根路径返回 404 是正常的）。闸门结论分四类，处置不同：
  - **通过** → 放行。
  - **真证书问题**（消息带 `证书校验失败` 前缀）→ 剔除该候选，并记进
    `certFailures`（默认 1 小时），后续写入直接跳过，省掉每次最多 8s 的握手。
    这份记忆是**硬边界**：候选全部被判死时不会回退到全量重试（见下一条）。
  - **临时链路问题**（超时 / ECONNRESET / 空响应等）→ 它**什么都没证明**，
    重试一次；仍失败则放行但标 `certUnverified`。这一条是「网络越烂越被卡死」
    的修法：拿超时当证书失败，等于让烂网络把自己锁死。
  - **认不出来的错误** → 没有安全证据，按不通过处理。
  - 闸门是**逐候选过滤**，不是全有或全无：首选证书失败不会连累已通过校验的备选。
    只有全部候选都不通过才如实返回失败
  - **候选全部被判死时不再重试**：`decide()` 直接给 `no-candidate`，`apply()` 直接
    失败并说明「已记下并暂时跳过」。回退到全量重试会让每一拍都重新握手一遍、
    注定失败、3 秒后再来——记忆等于没记。`candidates` 为空（还没测过）与「全被判死」
    分开措辞，前者不会谎称「证书都不适配」
- 写入：最优在前；**合格候选 ≥2 写 2 个，仅 1 个合格就写 1 个**；
  **0 个合格候选时按同样顺序取 1–2 条最不坏的**（优先避开 hosts 里已钉着的 IP，
  结果带 `degraded=true`，不再「不拿淘汰项凑数」）
- **手动「立即切换」永不被拒绝**：不受 `autoWrite`、差距不足影响，
  0 合格时同样降级写入；只有「一个候选读数都没有」才失败（原因由后端给）。
  能拦下它的只有「全部候选都过不了证书闸门」与写盘错误本身
- 全劣化写入时，若候选的**丢包率比当前线路更高**，结果带 `lossy=true`，
  文案说「已切到延迟较低的一条（丢包更多）」而不是「相对较好」——
  仍然写入（按钮点了就要动），但不谎报它更好
- **写入的域名 = 当前启用的地址**（不再沿用旧标记段里的域名），闸门校验的集合与实际写入的集合是同一个
- 备份：**单份 `hosts.bak` 覆盖**，无时间戳增量
- 写完 `flushdns` 即结束。**不做写入后观察、不自动切回**
- **没有每日切换次数上限**（2026-10-28 按用户要求整体删除）。
  自动切换的闸门只剩两个，都跟「值不值得」有关、跟次数无关：阈值够不够、
  全劣化时丢包是否更差。理由：网络质量本身在变，用固定次数拦住「该切」，
  只会让人被烂死在一条线路上——那正是这个插件要解决的问题本身。
  切换历史仍写进 `state.json` 的 `switchLog`（只写不读），用于事后确认
  「到底有没有真的写过 hosts」

## 非管理员

- **不提权**：UAC 需要用户在安全桌面自己确认，插件无法自动完成，所以「没权限」
  表现为一个被显示出来的状态，而不是一个弹窗。
- 自动切换在判定这一步止步：差距够了、该切、`admin === false` → 理由
  `need-admin`，不再往下执行。`autoWrite` 的取值由用户决定——配置归一化只认
  `autoWrite === true`，插件不会因为权限把它改成 `false`：权限不是配置，它只决定
  这一步能不能执行。
- 判定的顺序是「值不值得 → 有没有权限 → 要不要自动写 → 有没有流在飞」。所以对
  非管理员来说，只要真的有一条更快的线，状态就是 `need-admin`——哪怕 `autoWrite`
  是关的。这是有意的：那句话说的是「这台机器现在换不了」，而不是「你关掉了自动
  切换」，后者只对能换的人成立。
- 「需要管理员权限」只在**确实有一条更快的线、确实该切、只差权限**时显示；
  冷启动 / 断网 / 观测中等与权限无关的状态照常显示它们自己。
- 手动「检测」「写入」两个按钮空闲时始终可用（不受权限、不受 `autoWrite` 限制）。
  「写入」会真的执行到写盘，被权限挡下时报出后端给的原因，不做二次确认。

## 手动操作

手动路径有两个入口，走同一对后端接口。

### 点图标 = 测速 + 写入（主路径）

1. 点一下图标 → `POST /scan`（完整 scan 语义，同 `cf_pin.py scan`）
2. 扫描返回后播 **1400ms 刹车收尾动画**（引擎把阶段写成 `brake`，客户端等满 1400ms）
3. `POST /apply` 真写一次 hosts；结束立刻拉一次快照，不等下一个 4s 轮询

- 图标在两种情况下 `disabled`：正在测速（含**别的会话**在测速，即 `manual.busy`），
  或断网。读屏文案同步换成「正在测速」/「断网，暂不可测速」——读屏用户不该被告知
  可点、实际点不动；`disabled` 还会踢掉焦点，让键盘用户的 `:focus-within` 提示中途消失。
- 不做乐观更新：屏幕上出现的结果只来自 `/state` 快照。它真的会改用户的 hosts，
  不能先假装成功。
- 「没测到数据」与写入失败的文案由引擎的 `manual.note` 给出——引擎知道候选数，
  客户端不重复造一句自己的话。
- 动效由皮肤内部完成：`scan` → `spin`，`brake` → 缓停。引擎的阶段只表达「后端
  真的在做什么」，1400ms 的刹车是纯客户端动画，不写回公共状态。

### 配置页按钮

- **「检测」** = `cf_pin.py scan` 的完整语义（粗筛并发 96 → 读机房 40 个、并发 10 →
  实测 12 个、并发 12，约 1 分钟）。点一次就重扫一次，不复用上一轮的结果——
  按下按钮就是想要此刻的答案。
- **「写入」** = `apply` 语义，不受 `autoWrite` 影响，空闲时不禁用。
  没有合格候选时也会真的写入（写最不坏的 1–2 条，结果带 `degraded`）；只有「一个候选
  读数都没有」才失败，原因由后端给出。**不设二次确认**——按下就是执行一次，
  能拦下它的只有写前的证书闸门与写盘错误。
- **「取消固定」** = `unpin` 语义：删掉 hosts 里的 `CLOUDFLARE-PIN` 标记段、回退
  系统 DNS，返回 `removed`（`false` = hosts 里本来就没有固定段）。只动 hosts、
  不动配置，也不进 switchLog。取消之后**不会自动再钉回去**：标记段没了就没有
  「当前 IP」，自动判定会停在冷启动（不替你决定要不要接管机器）；要重新固定就点
  一次「立即切换」（或跑 `cf_pin.py`）。面板上要点两下（第一下按钮变成
  「确认取消固定？」，第二下才真的执行）。
  这是所有候选都烂到不值得固定时，插件内唯一的逃生口。
- 三个动作按钮的禁用条件都包含引擎的忙碌状态：图标那边在测速时，它们一并禁用，
  检测 / 立即切换两枚还把文案换成「检测中…」「收尾中…」「写入中…」，不再撒谎说
  「立即检测」。本页开关仍只由本页自己的动作锁住，不会因为另一个会话点了图标就
  整页变灰。

## 跨会话状态：`snapshot.manual`

引擎在宿主进程里**全局唯一**，而界面可以同时开着多个会话，每个会话的横幅是独立
组件。所以「正在测速」这类状态只有一份真相：写在引擎里，经 `/state` 快照的
`manual` 广播给所有会话。

契约：

| 字段 | 含义 |
|---|---|
| `phase` | `''` 空闲 / `scan` 扫描中 / `brake` 收尾动画 1400ms / `write` 写入中 |
| `startedAt` | 本次手动操作开始的时刻；**中途换阶段不重置**，界面上「已经忙了多久」才不会跳 |
| `note` | 阶段说明或上一次操作的结果（「测速中…」「已切到 1.2.3.4、5.6.7.8」） |
| `busy` | 等价于 `phase !== ''`；按钮禁用与忙碌动效只认它 |

两个存活期，都在引擎里判定：

| 常量 | 值 | 作用 |
|---|---|---|
| `MANUAL_TTL_MS` | 90s | 任何阶段超过它一律视为已结束。客户端崩溃、关页、被切走后没人收尾，状态也不会永久停在「测速中」 |
| `MANUAL_NOTE_MS` | 4.2s | 空闲时结果文案的存活期。忙碌期间 `note` 是进度说明，跟着阶段走，不受它约束 |

**为什么放在引擎**：两个过期都**在读快照时判定**，不起定时器——过期不需要谁来
触发，也不怕客户端不在。idle 的文案过期、阶段超时归零，都在一次
`manualNow()` 里算清，客户端拿到的永远是「此刻有效」的那一份。放客户端就做不到：
每个会话各有一份计时器，你清我不清，而且客户端一崩就没人清。

状态该不该提到引擎，判据是「它是**插件此刻的状态**，还是**我这个组件正在做什么**」：

| 状态 | 来源 | 为什么 |
|---|---|---|
| 状态码、四档、`has-better`、`is-stale`、`is-dead` | 快照 | 一直是全局的 |
| 忙碌、阶段、测速/结果文案 | `snapshot.manual` | 引擎唯一，各会话共享 |
| `is-arriving`（落位） | `snapshot.firstReadingAt` | 判据必须是「全局首次有读数」，否则每切一个会话都重播 |
| `is-swap` / `is-donor`（换线） | `current.ip` / `lastSwitch.at` 的变化 | 每个会话「亲眼看到变化」才播，切过去不补播 |
| 配置页展开、二次确认、输入框草稿、一次性提示、读数闪烁 | 组件本地 | 表达「我正在做什么」，全局化只会让两个页面互相干扰 |

## 悬停提示：`.cfp-tip`

图标常态零文字，悬停或聚焦时给一份注脚，补上纯视觉表达不了的毫秒数：

```
当前  312ms
候选  128ms
候选读数已过期        ← 只在候选读数过期时出现
```

- **纯 CSS 触发**：`.cfp-cluster:hover .cfp-tip` / `:focus-within`，没有 JS state。
  它是图标的注脚，不是插件状态，不需要跨会话同步。
- 数字取 `curMs` / `bestMs`，与图标档位**同源**，不会出现「图标说优、提示说
  600ms」；提示给到个位，比四档更有信息量。
- **不编数字**：断网 → 「断网，测不到」；候选是借用值 → 「沿用当前（尚未测速）」；
  没有读数 → 「暂无数据」。候选读数过期时多出第三行「候选读数已过期」。
- `aria-hidden="true"`：同样的信息已经在按钮的 `aria-label` 里，不隐藏会让读屏
  用户听两遍。键盘用户走 `:focus-within` 照样能看到。
- 触屏用 `@media (hover:none)` 关闭——触屏的「悬停」会在点击后粘住。
- 定位基准是 `.cfp-cluster`（宽度贴合图标、本身 `position:relative`），不是撑满
  整行的 `.cfp-dock`：后者会让 `left:0` 把提示推到窗口最左边。溢出边界在
  [UI-SPEC.md](UI-SPEC.md) §3.3.1 按宿主实际留白算过，不需要为它改定位基准。

## 数据与状态

```
$DSH_HOME/cf-pin-data/<profile>/
  config.json     面板改过的配置（不存在即用 patch / 默认值）
  state.json      切换历史（switchLog）+ 候选轮换指针 rotation + 手动轮换指针 manualRotation
```

不放插件目录，因为 `node_modules` 升级会覆盖。

**`switchLog` 只写不读，且裁到最近 24 小时**（`SWITCH_LOG_TTL_MS`，由
`pruneSwitchLog()` 在写入与读回两处执行）。它是「到底有没有真的写过 hosts」的
唯一可信证据——`hosts` 的 mtime 会被 `copyFileSync` 与别家工具干扰，这个数组不会。
**它同时是判断「插件是否生效」最干净的行为判据**：窗口里最旧的那条会随墙钟右移，
条数不随运行时长增长。如果最旧那条一直停在同一个值，说明要么没在写、要么跑的是
没有 `pruneSwitchLog` 的旧代码。

**当前 IP 永远以 `hosts` 标记段第一行为准**——hosts 是唯一真相，不信任何缓存。
轮换指针与计数从 `state.json` 读，冲突时以 hosts 为准。

## 结构

```
index.js              插件入口：定时节奏、llm/stream 挂载、9 条 HTTP 路由
lib/engine.js         探测调度、统计聚合、判定、写入执行、快照、manual 状态与过期
lib/probe.js          TCP / TLS / 百分位 / 并发限制（测量原语）
lib/hosts.js          hosts 读写：标记段、备份、原子替换、刷新 DNS
lib/config-store.js   配置持久化
lib/admin.js          管理员判定（不提权）
lib/types.js          内部类型
client.js             浏览器半：配置页 + 会话横幅 + 两套皮肤的渲染
UI-SPEC.md            图标规格：尺寸、四档口径、两套皮肤读法、动效时序、色彩
```

路由全在前缀 `/api/dsh-cf-pin` 下，9 条：`/state`（读快照，唯一的状态来源）、
`/scan`、`/apply`、`/unpin`、`/config`、`/addresses`、`/addresses/reset`、
`/reset`、`/reveal`。`/scan` 与 `/apply` 在进入时写 `manual` 阶段，退出时收尾，
所以浏览器半不用自己猜这时候该显示什么。

**收尾必须无条件执行，即使这次调用合并进了别人那一发。** `merged` 只说明「并进了
正在跑的那一份」，而那一份可能是**自动路径**的写入（候选轮末尾的 `decideAndApply()`
或思考流结束时的 `drainPending()`），自动路径从不管理 `manual` 阶段。原实现只在
`merged !== true` 时收尾，于是合并时无人收尾，`write` 阶段一直挂到 `MANUAL_TTL_MS`
（90 秒）自己过期——图标持续「写入中…」、配置页三个按钮全灰。现在收尾逻辑在引擎的
`finishManualWrite()` 里，无条件调用，并由它自己判断「阶段是否仍是 `write`」
（请求在飞时客户端可能已经开始了别的动作，不能把它的阶段清掉）。

两个半边的分工：

- **浏览器半不持探测状态。** `probing` / `probePhase` / `probeNote` 全部由
  `snapshot.manual` 派生（`phase` 映射成 `data-probe-phase` 的 `spin` / `brake`），
  配置页那两个动作按钮读同一份，所以「图标点了测速、切到配置页」看到的是同一件事。
  本地只留「我正在做什么」：设置折叠、二次确认、输入框草稿、一次性提示、读数闪烁。
- **`firstReadingAt` 是全局判据。** 落位动画要求两件事同时成立：这个组件第一次
  拿到快照，**且** `|now - firstReadingAt|` 小于 8000ms（`ARRIVE_WINDOW_MS`，
  比一个轮询周期宽、又短到几十秒后新开的会话不会误判）。第二个条件必须是全局的：
  每个会话的横幅是独立组件，只看「本组件第一次拿到数据」，每次切会话都会重播一次
  落位动画，而图标其实一直都在。
- 轮询 4s 一拍（`POLL_MS`），只在「上一发还没落地」时跳过，页面隐藏时也照常。

## 自测

测试分**两层**，别把两层混为一谈。

```powershell
cd <插件目录>

# ---- 离线层：只测决策与渲染，不联网、不碰系统 hosts（走临时文件）----
node _tools\regression-check.mjs         # 227 通过 / 0 失败
node _tools\motion-check.mjs client.js   # 19 场景 / 0 失败

# ---- 联网层：测量口径与证书闸门，会真的发连接 ----
node _tools\net-check.mjs --math         # 41 通过，不联网，退出码只有 0 / 1
node _tools\net-check.mjs                # 59 通过 / 2 SKIP，退出码 2（见下）
```

覆盖范围：

- `regression-check`：写入链路 / 启用域名 / 默认值 / 状态机 / `manual` 契约
  （跨会话一致、TTL 过期、文案存活期）/ 手动路径并发合并 / CSS 模板括号平衡。
  另有两段**行为**覆盖（2026-10-30 新增）：
  - `[ROUND]` 用假探针（`new Engine({ probe })`）整轮跑候选轮本体，断言分档排序、
    全超时真的重扫、只重扫一次、`p95` 触顶但零丢包不触发重扫、并发守卫仍有效。
  - `[CERTMEM]` / `[SNAPSHOT]` / `[MANUAL]` 断言证书记忆真的止住重试、快照外显
    `tier` / `certFailed` / `streaming` / `advantageMs` / `thresholdMs`、`best` 与
    `decision` 同口径、合并写入后手动阶段被收尾。

**这两段是为了修一个具体的教训**：候选轮此前只有源码正则断言（「那几行写着」），
于是「全超时重扫是死代码」在 154 条全绿的断言下藏了一轮。凡是「只有正则断言」
的地方，都应该补一条真跑的。

**反向验证**（改完实现按 §自测 的约定做）：把上面每条修复改回原缺陷，对应断言必须变红。
本轮 6 个篡改点全部被抓到（重扫入口 ×1、证书兜底 ×2、`tier` 外显 ×1、
`best` 过滤 ×1、manual 收尾 ×1）。

- `motion-check`：两套皮肤 × 四档 × 各状态、跨会话一致、切会话不重播落位、
  悬停提示、配置页读 `manual`、最近错误可见。

### 联网层：`net-check.mjs`

现状（2026-10-29 实测）：**59 通过 / 2 SKIP / 退出码 2**。

2 条 SKIP 是稳定环境事实，不是随机波动：

| SKIP | 原因 |
|---|---|
| 反例：主机名不匹配（1.1.1.1） | 本机到 `1.1.1.1:443` 不通（tls timeout），闸门没被触发 |
| 反例：非 CF IP（8.8.8.8） | 同上 |

「链路不通 → SKIP，不是 FAIL」是对的：闸门在那种情况下**根本没跑**，判它通过是
假绿、判它失败是假红。但 **`exit 2` ≠ 全绿**：它的含义是「没有失败，但覆盖不
完整」。本地复跑时把 `2` 读成「这两条负例这次没验到」，不是「都过了」。同一次
运行里真正被证书拦下的负例是 223.5.5.5 那条（证书不覆盖 `amr-link.open-design.ai`），
它必须有 `ok`——那条才是「闸门真的会拦」的证据。

### 为什么必须有联网层

证书闸门是**唯一的写前安全边界**。离线测试把 `verifyCert` 注入成假函数，
只能验证「闸门通过时写什么、不通过时不写什么」这套决策逻辑——
**它永远回答不了「真闸门会不会把坏 IP 放过去」**。同理，`probeDomain` /
`tcpRtt` / 百分位这些是插件存在的理由，离线测不出真行为。

这个分层不是多余的：本次审计中，正是联网层抓到了一个离线测试根本发现不了的严重 bug——
`certOk` 的文档说「判定标准就是 TLS 握手能完成」，实现却是「发 `GET /` 并等响应」，
而 `amr-link.open-design.ai` 的 `GET /` 在这条链路上经常不回包（同 IP 换
`/v1/models` 或 `/cdn-cgi/trace` 就有响应）。结果是**健康 IP 被随机判成证书失败**，
换线随之随机失败。离线层当时全绿。

### 联网层的失败语义

- **链路不通 → SKIP，不是 FAIL。** 脚本先用 TCP 做基线探测；不通就如实跳过并报告。
- **正例的 IP/域名必须成对取自 hosts 标记段。** CF anycast IP 按 SNI 路由，
  随便拼一个 IP + 另一个域名可能根本不通，那种超时是正常的、不是 bug。
- **反例必须真的走完证书校验才算数**：断言的是「证书被拒（消息里点名证书校验失败）」，
  而不是「连不上（ok=false）」。链路不通时如实 SKIP——把「连不上」当「拦下了」，
  就是旧版那种假绿：闸门坏掉也照样绿。
  脚本用一个本机可达、证书不可能覆盖该域名的公网 DoT 端点（223.5.5.5）来保证这条
  负例有真实覆盖；它不可达时同样 SKIP，不会假红。
- **退出码**：`0` = 全部通过；`1` = 有失败；`2` = 有跳过（有不完整覆盖）。
  以前「一条都没测成」也会以 0 退出，和真的全过分不开；现在用 2 表示「没验证到」，
  CI 或人都不该把它读成全绿。`--math` 不联网，只会有 0 / 1。
