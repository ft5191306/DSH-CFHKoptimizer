# dsh-cf-pin — 优选线路

持续测量 `open-design.ai` 这条链路上的 Cloudflare 边缘 IP，链路劣化时自动改写
`hosts` 的优选段。

这个插件是同一份测量策略的**常驻化版本**：原来的手动脚本 `cf_pin.py` 保留为
手动逃生通道（需要从头扫一遍、或怀疑候选池本身时用它）。

## 为什么需要它

这些域名走 Cloudflare anycast，同一条线路上会落到不同机房。境外链路默认常被甩到
LAX，国际链路丢包严重：API 请求动辄秒级超时。而 `162.159.x` / `104.26.x` 这一段
会落到 HKG，同一个请求 200ms 出头。`hosts` 把域名钉到特定边缘 IP 就能改掉落点。

IP 会慢慢劣化。手动跑 `cf_pin.py` 要快一分钟，而「变慢」这件事用户是事后才察觉的。
所以这个插件做的是：**平时不打扰，劣化时自己换掉。**

## 职责边界（重要）

**不做全量发现。** IP 已经过多轮实测选好，插件不重复这件事。它只做两件：

1. 判断当前链路是否劣化（相对一个更快的候选，差距是否 ≥ 150ms）
2. 该换时按 `cf_pin.py` 的同一套安全规则写 `hosts`

需要从头扫一遍、或怀疑候选池本身时，仍然去跑 `cf_pin.py`。

## 测量口径（全部来自 cf_pin.py 的实测校准，不是这里拟的）

| 项 | 值 | 理由 |
|---|---|---|
| 采样窗口 | **20s 硬上限** | 约 40 个样本，p95 才真正代表「1/20 的偶发卡顿」；5s 窗口的 p95 几乎等于最差值 |
| 采样间隔 | 50ms（下限） | 实际节奏由 RTT 决定；同一地址不并发抢带宽 |
| 单次 HTTPS 超时 | 1.5s | 完整请求正常约 500ms。用 TCP 的 0.3s 会把健康请求全误判成超时 |
| 超时记账 | **按 999ms 计入样本，不丢弃** | 丢弃会让「10 次卡 1 次」的 IP 看起来完美，而那一次卡顿正是用户感知到的 |
| 淘汰 | 最差地址的 p95 ≥ 999 | 时断时续的 IP 不是「慢一点」，写进 hosts 会随机卡死 |
| 排序 | 合格者按各地址 p50 平均 | p50 样本多、最稳定；p95 对单次抖动过敏，只作淘汰判据 |
| 百分位 | 线性插值（numpy 口径） | n=40 时 nearest-rank 会在 2 个超时就淘汰，这份口径要到 3 个 |
| TCP | 只做存活粗筛 | 实测 8 个 IP 的 TCP 全在 78~103ms（噪声内），HTTPS p50 却是 257~385ms；TCP 第一名在 HTTPS 排第四 |
| 候选池 | 162.159/16 + 104.26/16，各隔 2 个 /24 取 1 = 256 | 实测这一步拿到的近端候选比全量扫描还多，且快 3 倍 |
| 近端机房 | HKG NRT KIX ICN SIN TPE BKK MNL SGN | 远端机房差一个数量级（HKG ~500ms vs LAX ~2600ms），不进候选 |

**两条节奏是分开的，新鲜度差 25 倍：**

- 当前 IP：默认 **6 秒**测一次，取**最新一次**值（无滚动窗口）。它要能立刻反映此刻的体感。
- 候选轮：默认 **150 秒**一轮（12 候选 ÷ 2 并发 × 25s 槽位），每 **5 分钟**启动一轮。

任何把这两个数并排展示的界面都必须带上各自的年龄。

## 判定与写入

- 阈值：候选最优 p50 比当前低 **≥ 150ms**
- **无地板值、无「连续 N 轮」、无回切冷却**（用户明确否决过这些阻尼）
- 有思考流在飞 → 状态「等待写入」，流结束立刻写；**探测本身不避让**
- 写前闸门：启用的地址逐个做**真实证书链 + 主机名校验**。HTTP 状态码不参与判定
  （`amr-link` 根路径返回 404 是正常的）
- 写入：最优在前；**合格候选 ≥2 写 2 个，仅 1 个合格就写 1 个**（不拿淘汰项凑数）
- 备份：**单份 `hosts.bak` 覆盖**，无时间戳增量
- 写完 `flushdns` 即结束。**不做写入后观察、不自动切回**
- 24h 切换超上限（默认 12）→ 只提示不写；计数**持久化，重启不清零**

## 非管理员

`autoWrite` 强制降级为 false，界面显示「需要管理员权限」。**绝不尝试 UAC 提权**——
UAC 需要用户在安全桌面自己确认，插件无法自动完成。手动「检测/写入」按钮始终可用。

## 手动操作

- **「检测」** = `cf_pin.py scan` 的完整语义（粗筛并发 96 + top12 实测轮并发 12，约 1 分钟）。
  **同会话内不重复扫 256**，结果缓存复用。
- **「写入」** = `apply` 语义，**永不禁用**，不受 `autoWrite` 影响。
  全部候选被 p95 淘汰时仍可点，但需要二次确认。

## 配置

面板里可改，改动立刻落盘到 `$DSH_HOME/cf-pin-data/<profile>/config.json`，重启后仍生效。

| 项 | 默认 | 说明 |
|---|---|---|
| `autoWrite` | false | 判定成立时是否真的写 hosts |
| `showUi` | true | 是否在输入框显示状态图标。关掉后只是不画，测量与自动切换照常 |
| `skin` | `ring-core` | 图标皮肤：`ring-core`（环芯）/ `afterglow`（余温） |
| `currentProbeMs` | 6000 | 当前 IP 采样间隔 |
| `candidateConcurrency` | 2 | 候选轮并发，**直接决定一轮时长** |
| `roundIntervalMin` | 5 | 候选轮间隔，受并发下限约束 |
| `switchThresholdMs` | 150 | 判定的最小优势 |
| `maxSwitchesPerDay` | 48 | 24h 自动切换上限，可下调（1–48） |
| `probeWhileThinking` | false | 思考中是否继续探测 |
| `addresses` | 3 个 open-design 域名 | 每项带启用勾选；启用项才参与探测 / `cert_ok` / 写入 |

图标的完整规格（尺寸、四档口径、两套皮肤读法、动效时序、色彩）见 [UI-SPEC.md](UI-SPEC.md)。

**不开放**：20s 采样窗口、25s 槽位。这两个是测量口径的一部分，不是旋钮。

并发 → 一轮时长：

| 并发 | 组数 | 一轮 | 轮间隔下限 |
|---|---|---|---|
| 1 | 12 | 300s | 5 min |
| **2（默认）** | **6** | **150s** | **3 min** |
| 3 | 4 | 100s | 2 min |
| 6 | 2 | 50s | 1 min |
| 12 | 1 | 25s | 1 min |

## 数据与状态

```
$DSH_HOME/cf-pin-data/<profile>/
  config.json     面板改过的配置（不存在即用 patch / 默认值）
  state.json      切换历史（24h 上限的计数）+ 轮换指针
```

不放插件目录，因为 `node_modules` 升级会覆盖。

**当前 IP 永远以 `hosts` 标记段第一行为准**——hosts 是唯一真相，不信任何缓存。
轮换指针与计数从 `state.json` 读，冲突时以 hosts 为准。

## 结构

```
index.js              插件入口：定时节奏、llm/stream 挂载、HTTP 路由
lib/engine.js         探测调度、统计聚合、判定、写入执行、快照
lib/probe.js          TCP / TLS / 百分位 / 并发限制（测量原语）
lib/hosts.js          hosts 读写：标记段、备份、原子替换、刷新 DNS
lib/config-store.js   配置持久化
lib/admin.js          管理员判定（不提权）
lib/types.js          内部类型
client.js             浏览器半：配置页 + 会话横幅 + 两套皮肤的渲染
UI-SPEC.md            图标规格：尺寸、四档口径、两套皮肤读法、动效时序、色彩
```

## 自测

```powershell
cd <插件目录>
node _tools\motion-check.mjs client.js   # 图标渲染：两套皮肤 / 四档 / 各状态（10 场景 40+ 断言）
node _tools\selftest.mjs      # hosts 语义 / 百分位 / 淘汰边界 / 派生读数（22 项，不联网）
node _tools\engine-check.mjs  # 状态机 / 判定 / 每日上限 / 持久化（25 项）
node _tools\route-check.mjs   # 路由与配置归一化（26 项，不写系统 hosts）
node _tools\net-check.mjs     # 真实网络：TLS 口径 / 证书闸门
node _tools\round-check.mjs   # 真实跑一轮候选轮（约 3-4 分钟）
```

前三个不联网、不碰系统 `hosts`，可以随便跑。`round-check` 会真实发起 256+ 次连接。

## 与本机关系

DSH 宿主的 `baseURL` 就是 `https://amr-link.open-design.ai/v1`，所以这条链路的
质量直接决定这个客户端本身快不快。这也是为什么它值得做成常驻插件，而不是
一个想起来才跑的脚本。
